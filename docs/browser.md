# ブラウザ対戦ツール（対AIモード）の使い方

ブラウザの盤面で **主人公3人（A・B・C）を1人で操作し、自動の脚本家と対戦** します。
ルールの処理（行動の解決・能力・事件・ループの終わり）はエンジンが行い、画面には公開情報だけが出ます。

> ルールそのものの説明は含みません。惨劇RoopeR のルールを知っている前提です。

## 1. 起動

準備（[README の「インストール」](../README.md#インストール)）が済んでいれば、ターミナルを2つ使います。どちらもリポジトリの根で実行します。

**いちばん簡単な起動（開始画面つき）**: ターミナル1つで、サーバーが進行役も起動します。

```bash
SANGEKI_AI=1 SANGEKI_PYTHON=.venv/bin/python SANGEKI_GAME=game_ai PORT=8766 node server.mjs
```

ブラウザで **http://localhost:8766/** を開くと、まずタイトル・免責事項・遊び方の案内が出ます。『ゲームを始める』で「新しいゲーム」の画面になり、
脚本・脚本家・乱数の種を選んで『開始』（試合の途中なら『続きから遊ぶ』で戻れます）。
既定は **脚本を伏せて遊ぶ**（おすすめの脚本から、遊んだことのないものを選ぶ。遊び尽くしたら自動生成の脚本から）と、**いちばん強い脚本家 `calcGBxhd`** です。
試合の途中や終わった後も、帯のディスクのメニュー →『新しいゲーム…』（終わった後は帯の『新しいゲーム』）で始め直せます。

- 脚本の一覧は、**おすすめ**（選び抜いた設計の脚本。選び方は [`research.md`](research.md) の「優秀な脚本（おすすめ）の選定」）・同梱の脚本・（sangeki-scripts があれば）設計した脚本の順です。題名は内容の手がかりになることがあるので、何も知らずに遊ぶなら「脚本を伏せて選ぶ」を使います（おすすめから、遊び尽くしたら sangeki-scripts の自動生成の脚本から選ぶ）
- **観戦の欄**: 自動同士では操作の欄が観戦の欄になります（演出の速さ・止める・最後まで・遅れ）。観戦の演出の速さの既定は「速い」です
- **主人公を自動にして観る（自動同士）**: 開始画面の「主人公」で、自動の主人公を選べます。`read2`（推理する）・`read`（推理する・速い）・`lockQA`（推理する・強い。どこからともなく置かれたカウンターの置き先も手がかりにする）・**`oreadKQL`（脚本を知っている。配役・ルール・犯人を知り、伏せ札の中身は知らない。最後の戦いは本当の配役で答える）**。
  脚本を知っている主人公は、ループを守ることを先に考えます: 脚本家の伏せ札の置き先を見て、中身がどれでも今日の後にループが確定しない応手に絞り、
  その中で、その日の事件まで進めた盤面で勝ち目の大きい手を選びます（v0.7.0。v0.6 の `oread` の記録もそのまま再生できます）。
  自動同士で最後まで進み、盤面・ログ・場面カードはふだんどおり出ます。終わったら『リプレイを保存』『URL をコピー』でログを残せます（記録に主人公の種類と乱数の種が入り、同じ試合を作り直せます）。
  進行役を直接起動するなら `python ai_gm.py --pc read2 --mm calcGBxhd --script designed/d07 --seed 3 --dir DIR`（何試合も作るときはこれを並べる）
- 開始画面で選べる脚本家は `calcGBxhd`（既定・最強・1手に数秒〜数十秒。1日目がいちばん重い）・`calcD`（強い・1手に数十秒）・`calcG`（強い）・`searchL`・`search`（速い）・`route`（最速）
- 脚本を一覧から選ぶこともできますが、**脚本のタイトルから脚本の内容が分かる可能性があります**
- 伏せて遊ぶには sangeki-scripts（おすすめの設計の脚本・自動生成の脚本）が必要です。無いときは一覧から選びます
- `?ux=off` では案内を出さず、すぐ「新しいゲーム」の画面になります
- `SANGEKI_PYTHON` は Python の場所（仮想環境の python。省くと `python3`）
- `SANGEKI_WORKERS` は自動の脚本家の思考の並列の数（既定はコア数−1、最大6。`1` で並べない。詳しくは [`cli.md`](cli.md)）

**進行役を自分で起動する場合**（ほかの脚本家の型を使う、など）: ターミナルを2つ使います。

```bash
# ターミナル1: 盤面のサーバー
SANGEKI_GAME=game_ai PORT=8766 node server.mjs

# ターミナル2: 進行役（エンジンと自動の脚本家）
python ai_gm.py --script s03_bomb --mm calcG --seed 1
```

ブラウザで **http://localhost:8766/** を開きます。

- `SANGEKI_GAME` と `ai_gm.py --dir`（既定 `game_ai/`）は同じ場所を指すようにします。盤面と進行役はこの置き場所のファイル
  （`state.json`・`log.jsonl`・`inbox.jsonl`）でやりとりします
- サーバーは自分の PC の中だけで動きます（既定で `127.0.0.1`）。他の端末から開くときは `HOST=0.0.0.0` を付けます（信頼できるネットワークでだけ）
- 進行役のオプション: `--script`（脚本）、`--mm`（自動の脚本家）、`--seed`（乱数の種）、`--blind`（脚本を伏せて選ぶ。おすすめから、遊び尽くしたら自動生成から。`--blind-pool generated` で自動生成だけから。sangeki-scripts が必要）

### ブラウザだけで動かす版（Pyodide、試作）

Python（エンジンと自動の脚本家）をブラウザの中で動かす版です。サーバーは静的なファイルを配るだけで済みます（GitHub Pages などに置ける）。
盤面はサーバー版と同じ `board.html` を使い、サーバーへの要求をブラウザの中で答える小さなスクリプト（`web/shim.js`）を差し込みます。

```bash
bash web/build.sh                      # web/dist に組み立てる（画像は assets/ があれば写す。--no-img で写さない）
cd web/dist && python3 -m http.server 8784   # http://localhost:8784/ がトップページ、/play/ が対戦画面
# → http://localhost:8784/
```

- Python は [Pyodide](https://pyodide.org/)（v314.0.7、CDN から読み込む。初回は約30MB）。人の操作を待つところに JSPI を使うので、**Chrome・Edge の最近の版**で動きます（Firefox・Safari は未対応の見込み）
- 自動の脚本家の計算はブラウザを動かしている PC で行うので、速さは PC の性能に左右されます。脚本家の種類によっては手の計算で待たされます（calcG の1日目の伏せ札は、手元の計測で約25秒でした）
- **自動の脚本家の思考を並列にします（補助の Web Worker）。** ページを開いた後、補助の Worker を裏で2つ読み込み、主人公の応手を読む計算を3つに分けます。
  手は並べない場合と同じです。手元の計測（ヘッドレスの Chrome、calcGBxhd の1日目。いちばん重い手）で 22秒 → 16秒。補助の読み込みが終わるまでは1つで計算します。
  補助1つにつきメモリが 200MB 前後増えます。数は `?helpers=N` で変えられます（既定 2、最大 4、`?helpers=0` で使わない）
- CDN に届かない環境では `PYODIDE_DIR=<npm の pyodide パッケージ> bash web/build.sh --local-pyodide` で同梱し、`?pyodide=local` を付けて開きます
- 根（`web/dist/index.html`）は検索向けのトップページ（`web/landing.html`。題名・説明・OGP・構造化データ・`robots.txt`・`sitemap.xml`）で、対戦画面は `web/dist/play/` です。根に `#p=` や `?replay=` などが付いた URL（以前に共有したリプレイ・再開の URL）は、そのまま `play/` へ送ります。共有の画像（`og.jpg`）とトップページの絵（`hero.jpg`）は組み立てのときに惨劇コモンズ5th から作ります（Pillow が要る）
- 盤面の状態・ログはブラウザのメモリの中だけにあります（再読み込みすると試合は消えます）。推理シートの書き込みはブラウザに保存されます

## 2. 画面の見方

```
┌──────────────────────────── 帯 ─────────────────────────────┐
│ ループ 1/3  日 1/6  [フェイズ]  リーダー A  いま何を待っているか │
├──────────────────────────────┬──────────────────────────────┤
│                              │ ログ                          │
│   盤面（病院・神社・都市・学校）│ 操作（公開シート帯・送信待ち・  │
│   キャラクター駒・カウンター・  │   脚本家の返答・友好能力・手札） │
│   伏せ札・置いた札             │ 推理（公開シート・マトリクス…）  │
└──────────────────────────────┴──────────────────────────────┘
```

**幅ごとの配置**（盤面は前の版より小さくしません）: 1800px 以上は 操作 300px と 推理 520px、1300〜1800px は推理 380px の列、900〜1300px は操作の下に推理を同じ列で、900px 未満は盤面のすぐ下に手札（置く番の主人公の分）と『確定して送る』、推理は下端の引き出し（押して開く）。欄の幅は右下のつまみで変えられます。

**帯**: ループと日、いまのフェイズ、リーダー、**いま誰の入力を待っているか**。使える友好能力があると件数のバッジが出ます。

**盤面**
- 4つのエリアのボードと、キャラクターの駒。駒のバッジはトークンの絵と「不安 2/3」（いまの不安／不安臨界）・「友好 n」・「暗躍 n」・「護衛 n」。不安は 0 でも点線で出し、**不安臨界以上は「! 不安 3/3 臨界」と赤枠**、あと1で臨界は点線の縁。駒が小さいときは絵を省き、さらに小さいと1文字（「不 2/3」）にします
- ボードの「暗躍 n」は、そのエリアの暗躍
- 脚本家の伏せ札は裏向きで置かれます。行動の解決で表になります
- 自分が置いた札は、送る前は点線の枠、送った後はフェイズが進むまで盤面に残ります

**右の欄**（見出しを押すと畳めます。畳むと盤面が広くなります）

| 欄 | 中身 |
|---|---|
| ログ | エンジンが処理した出来事（公開情報だけ）。役職などの理由は伏せられます。行の頭に種類の印（［札］［移］［カ］［脚］［能］［事］［死］）。見出しの欄で種類・人物名で絞り込めます。日ごとの見出しで畳まれ、最新の日だけ開いています |
| 操作 › 公開シート帯 | 惨劇セット・ループ（終わったループは取り消し線）・リーダー・特殊ルール・日ごとの事件予定とループごとの結果（今日の行に色）・いまのフェイズ（「3/9」）・脚本家の1ループ1回の札（暗躍+2・移動斜め）の残り |
| 操作 › 当日の流れ | その日に起きたことを9つのフェイズの枠で（済んだ ✓・いま ▶・これから ・）。行を押すとログのその行へ、『盤面』でその時点の盤面。前に操作した後に増えた行に「新」。『◀ 前の日』『次の日 ▶』でループをまたいで見返せる |
| 操作 › 送信待ち | 置こうとしている札・宣言。『確定して送る』で送信 |
| 操作 › 脚本家の返答 | 送った操作への返答（能力の解決・拒否など） |
| 操作 › 友好能力 | 宣言できる能力の一覧（使えるものが上に緑で並ぶ） |
| 操作 › 手札 | 主人公ごとの手札。★は1ループ1回の札で、使うと灰色 |
| 推理 | 自分用の推理シート（[5](#5-推理の欄)） |

## 3. 1日の流れと操作

帯の「いま何を待っているか」に従って進めます。自分の番でないときは、脚本家とエンジンの処理を待ちます
（`calcG` は1手に数十秒〜1分かかります）。

### ① 脚本家が伏せ札を置く

待つだけです。終わると帯に「行動カードを3枚（A→B→C）置いて『確定』。脚本家の伏せ札は 〇〇・〇〇・〇〇」と出ます。

### ② 主人公の札を置く

1. 置きたい **キャラクターかエリアを右クリック**
2. 「主人公A が札を置く…」→ 札を選ぶ（★は1ループ1回の札）
3. B・C も同じように置く → 「送信待ち」に3枚並ぶ
4. **『確定して送る』**

- **取り消し（送る前だけ）**: 送信待ちの行の × で1枚ずつ消す、『取り消す』で全部消す、同じ主人公でもう一度置くと置き直し（上書き）。
  手札の札を選んだ状態は Esc かもう一度クリックで解除。『確定して送る』の後は取り消せません
- 置き方の誤り（同じ対象に2人など）は画面では止めません。エンジンが判定し、反則なら「脚本家の返答」に理由が出ます（公開ログには入りません）

### ③ 行動の解決

自動です。6枚すべてが公開され、カウンターや移動がログと盤面に反映されます。

### ④ 脚本家能力フェイズ

自動です。脚本家の能力（ミスリーダーなど）の結果が「どこからともなく〇〇に不安+1」のようにログに出ます。

### ⑤ 主人公能力フェイズ（友好能力）

帯が「リーダーから友好能力を宣言」になります。

1. 「友好能力」の欄の **『宣言』** を押す（またはキャラクターを右クリック →「友好能力 …」）
2. 対象や選択肢を選ぶ（ルールXの宣言、事件の選択、カウンターの移し先など、能力ごとに聞かれます）
3. 1件ずつその場で解決されます。脚本家が拒否した場合も「脚本家の返答」とログに出ます
4. 宣言し終えたら、「送信待ち」の欄に出るボタン **『能力の宣言を終える』**（押すとすぐ送信されます）

- 同じ能力は1日1回、★は1ループ1回。友好が足りない能力は灰色ですが、宣言は止めません（エンジンが判定します）

### ⑥ 事件・ターン終了

自動です。事件の発生・不発、死亡、ループの終わりがログに出ます。翌日は①から。ループが終わると、次のループの準備も自動で進みます。

## 4. 最後の戦い

最終ループを落とすと（脚本によっては）最後の戦いに入ります。

ループ2以降の始めの**時の狭間**では、『次のループへ』か『最後の戦いへ進む（残りのループを飛ばす）』を選べます（主人公の書 印刷p20。以降のループは行えなくなるので主人公には不利）。最後の戦いの無い惨劇セットと、自動の主人公（観戦）では聞きません。

1. **キャラクターを右クリック →「役職を宣言する（最後の戦い）…」→ 役職** を選んで送る
2. 役職の候補には、人物×役職の格子の自分の印（◎・○・✕）が付いて並びます。格子の人物名からも宣言できます。宣言するたびに、その場で判定がログに出ます（「宣言: 男子学生 は キラー ― 正解」）。正解なら次の1人を宣言します。外れた時点で脚本家の勝ちです（主人公の書 印刷p25）
3. 残りを全員パーソンとするなら **『宣言を終える（残りはパーソン）』**。まだ宣言していない人の名前を並べて確かめてから、1人ずつパーソンとして判定します

ゲームが終わると、**非公開シート**のダイアログが出ます。勝敗と決め手、脚本の題名、ルール、全員の役職（最後の戦いの宣言との答え合わせつき）、事件と犯人を表で見られます。閉じた後も帯の『非公開シート』で開き直せます。ログにも同じ内容が出ます。

## 5. 推理の欄

各区切りは見出しを押すと畳め、📌 で一番上に固定できます（900〜1300px の幅では、ルール・事件・ループの記録を畳んで始めます）。

自分の推理を書き込むシートです。書いた内容は自動で保存され、再読み込みしても残ります（`game_ai/notes.json`）。書き込みは試合ごとで、新しい試合では前の試合の印は出ません。

| 表 | 使い方 |
|---|---|
| 公開シート | 脚本の公開情報（惨劇セット・ループ数・日数・事件予定・特別ルール） |
| ルール | ルールX・Y ごとに「不明・候補・消えた・確定」の印を付ける。確定が多すぎると「!」（Basic Tragedy X ならルールY は1つ・X は2つ） |
| マトリクス | ルールと役職の員数の対応 |
| 役職の能力 | 早見表の役職の能力 |
| 敗北条件 | 主人公の負け方の一覧。ループごとに起きたかを付ける |
| 事件 | ループごとの結果と不安臨界以上の生存者を自動で並べ、犯人の推測を書く。ログの行の『＋メモ』で、その行を人物のメモに引用できます |
| 資料 | キャラクターの公開情報と友好能力・役職の能力・ルールの追加ルール・事件の効果を、言葉で探す（例「暗躍」「ループ終了時」） |
| ループの記録 | ループごとの公開された事実: 事件の発生／不発と不安臨界以上の生存者、死亡、公開された役職、終わり方（どのフェイズで終わったか） |
| 人物×役職 | 列の見出しに、ルールの印と早見表の員数から数えた「必要 n」（自分の印からの計算。◎ が多すぎると「!」。⚙ で消せる）。人物名を押すとメモ欄へ、行に触れると盤面の駒が光り、駒のメニューを開くとその行に枠。『役職ごと』に切り替えると、役職を1つ選んで人物の札に印を付けられます（狭い画面の既定）。マスを押すたびに 空 → ○ 候補 → ✕ 違う → ◎ これ。◎ を付けると同じ行に薄い ·✕。「消えた」にしたルールにしか出ない役職の列は薄く。矢印キーで移動 |
| 登場人物 | 役職（格子の ◎ から）とメモ |

**エンジンの候補**: 推理の欄の見出しにある『エンジンの候補』を押すと、公開された出来事からルール上ありうる組み合わせを数えた割合が重なります
（確定＝緑、強い候補＝橙、消えた＝灰の取り消し線）。「狙い込み」は、脚本家が伏せ札を置いた場所から狙いを読んだ見込みです。
**答えを自分で考えたいときは押さないでください。**

## 6. 便利な操作

- **クリックで置く**: 手札の札をクリックしてから、キャラクターかエリアをクリック（タップ・Enter でも可、Esc で解除）。スマホ・タブレットでも使えます。**ドラッグ**でも置けます。札を選ぶと置ける所が点線で光ります。狭い画面では手札のトレイの A・B・C でほかの主人公の手札に切り替えられ（置く順には縛りません）、エリアの隅の ⤢ でそのエリアを大きく表示します。右クリックのメニューは矢印キー・Enter・Esc で操作でき、いまのフェイズで使える項目が上に並びます。
- **キーボード**: 1〜8 で札を選ぶ、Tab・矢印で置き先、Enter で置く、Ctrl+Enter で確定、Esc・Space で演出を飛ばす、? で一覧
- **過去の盤面**: ログの行の右端の『盤面』ボタンで、その時点の盤面を表示します。帯の『いまに戻る』で戻ります
- 「脚本家に伝える」の欄・「ハッシュでの固定」の欄・ログの行の右クリック →「異議を送る」は、人が進行役を務める手動モード用です。対AIモードでは表示しません

## 7. 表示の設定（場面カード・考え中・画像なし）

人が遊びやすいように、次の表示があります。帯の右端の **⚙** で個別に切り替えられます（設定はこのブラウザに保存）。

| 表示 | 中身 |
|---|---|
| **盤面の演出** | 盤面の変化を順に動きで見せます。行動解決はルールの順（主人公の書 印刷p22）: 脚本家の札がめくられる → キャラクターが移動する（向きの矢印。禁止エリア・移動禁止で止まったら文字） → カウンターのバッジがはずみ「+1」などが浮く（無効になった札は震えて「無効」） → 解決した札が持ち主の手札へ戻る。ほかに、主人公の札は手札から置き先へ、脚本家の伏せ札は画面の上から置かれる、どこからともなく置かれたカウンター（誰からとは示さない）、友好能力を使ったキャラクターと対象が光る、拒否・護衛、事件の発生／不発の見出し（犯人は指しません）、死亡、登場、公開された役職の札、リーダー交代、ループの敗北と巻き戻し、最後の戦いの宣言ごとの正解／不正解。試合は表示より速く進むので、盤面は場面を1つずつ順に見せます（遅れが大きいと飛ばして追いつきます）。当日の流れの各フェイズの『▶ 演出』で、その場面をもう一度見られます。演出中は **Space** か盤面のクリックで飛ばせます（たまった場面も最新まで送ります）。演出の速さ「なし」では動かさず、数字だけが変わり、変わったキャラクターに黄色の枠が次の操作まで残ります（端末で「視差効果を減らす」にしているときの既定） |
| **考え中** | 脚本家が考えている間、「脚本家が考えています（伏せ札）」・経過秒数・進み具合のバー・いまの段階を出します。最初の3秒は画面の中央、その後は右上に小さく。盤面は暗くしません。毎日ある待ち（伏せ札・ループの準備・送信の後）には「脚本家は事件の種をまいている」のような雰囲気の文が4秒ごとに入れ替わって出ます（決まった一覧から無作為に選ぶ文で、脚本とは関係ありません） |
| **自分の番** | 入力が要るとき、帯が緑になり、ブラウザのタブの題名が「★あなたの番」になります（別のタブを見ていても気づける） |
| **場面カード（日の終わり）** | フェイズごとの出来事は盤面の演出と当日の流れで見せ、カードは日の終わりだけにしました。1日が終わると「○日目の終わり」（ループの終わりは「ループ○の終わり」）のカードに、その日に起きたことをまとめて出します。**自動では閉じません**。『次の日へ』を押すまで次に進まないので、その日を振り返って考えられます（その間に脚本家は次の日を考えています）。観戦（自動同士）では日ごとのカードで止めません |
| **盤面を見る** | 場面カードを画面の下の細い帯に畳み、盤面をゆっくり確かめられます。『場面に戻る』で戻ります |
| **解決前／解決後** | その場面の処理の前と後の盤面を切り替えて見比べます。解決後では、変わったキャラクター（カウンター・移動・生死）を黄色の枠で強調します。帯の『いまに戻る』で今の盤面に戻ります |
| **キャラクターの説明** | キャラクターにマウスを乗せると、大きめの説明（不安臨界・カウンター・初期エリア・禁止エリア・属性・特性・友好能力）を出します |
| **画像なしの表示** | 盤面の画像が読めないとき（`setup_images.sh` を実行していないなど）は、自動で文字の表示になります。エリアは色分けしたパネル、キャラクターは名前の札、行動カードは短い名前の札（例: 暗+2・不−1・移↕、伏せ札は「伏」）。スマホでも名前が読めます |

⚙ の設定:

| 設定 | 選べる値 |
|---|---|
| 場面カード | 出す／出さない |
| 演出の速さ | ゆっくり・ふつう・速い・なし |
| 確定前の確認 | 1ループ1回の札・暗躍禁止が2枚以上・ボードに暗躍禁止以外のときだけ、3枚の要約と気づき（事実だけ）を出して確かめる。★の友好能力も宣言の前に確かめる |
| 初めての案内 | ループ1の1日目に、フェイズごとの1行の案内を出す（初めての試合だけ／いつも／出さない） |
| 簡単表示 | ログと推理の欄を畳む（盤面が広くなる） |
| 自動で閉じる | 秒数（0 で自動では閉じない） |
| 考え中の表示 | 出す／出さない |
| 画像 | 自動・あり・なし（文字） |

**URL での指定**（保存した設定より優先し、そのページだけ効きます）:

| URL | 効果 |
|---|---|
| `http://localhost:8766/?ux=off` | 場面カード・演出・考え中の表示をすべて切る（自動の試験や、素早い確認用） |
| `?ux=fast` | 演出を速くする |
| `?img=off` | 画像なしの表示にする（`?img=on` で画像あり） |

サーバーを `SANGEKI_NOIMG=1` を付けて起動すると、画像を配信しないので、誰が開いても画像なしの表示になります。

## リプレイ（書き出しと読み込み）

試合の記録（公開ログ・場面ごとの盤面・終了時の盤面と非公開シート）を JSON ファイルに書き出し、あとで読み込んで見返せます。
エンジンは使わず記録を順に表示するだけなので、サーバー版でもブラウザ版でも同じように動き、すぐ開けます。

- **書き出す**: ディスクのメニュー →『リプレイを書き出す（JSON）』、またはゲーム終了の非公開シートの『リプレイを保存』。試合の途中でも書き出せます（そのときは脚本の中身を含みません）
- **読み込む**: ディスクのメニュー →『リプレイを読み込む…』でファイルを選ぶ。画面の下に操作バーが出ます（⏮ 最初へ・◀ 1つ戻る・▶ 再生／停止・▶| 1つ進む・⏭ 最後へ・スライダー）。
  各場面の盤面と、そこまでのログを表示し、その場面で起きた行を青く強調します。終わった試合なら『非公開シート』も開けます
- **URL で開く**: `?replay=<リプレイの JSON の URL>` を付けて開くと、そのリプレイを表示します（人に見せるとき）
- 『リプレイを終える』で、いまの試合の表示に戻ります（リプレイを見ている間も試合は続いています）

## ディスクのメニュー（帯の右端、⚙ の左）

新しいゲーム・シナリオを作る（新しいタブ）・リプレイの書き出し（JSON）と読み込み・リプレイの URL・この場面から再開する URL。

## リプレイの JSON から URL を作る（道具）

```bash
python -m selfplay.rebuild_record replay.json              # 短い URL（判断の記録が無ければ公開ログから組み立て直す）
python -m selfplay.rebuild_record replay.json --resume-at 246  # 公開ログ 246 行目の場面から再開する URL
python -m selfplay.rebuild_record replay.json --long       # 盤面の記録ごとの長い URL も
```

判断の記録が無い（以前に書き出した）リプレイは、公開ログから両陣営の判断の候補を作り、エンジンで再生して公開ログが一致するものを探します（数十秒）。
脚本はリプレイの終了時の非公開シートから、脚本家の型は開始のログから読みます（途中までのリプレイは `--script` で指定）。`--base` で盤面の URL を変えられます。

## URL での共有

- **リプレイ**: ディスクのメニューの『リプレイの URL をコピー』、終了時の非公開シート、リプレイ表示中の『URL をコピー』。URL の `#` の後ろに入れるので、サーバーには送られません。
  - **短い URL（`?p=`、約1,000文字。以前の `#p=` も開ける）**: 主人公の操作と脚本家の判断（record.json）だけを入れ、開くときにエンジンで試合を作り直します
    （エンジンのルール処理は乱数を使わず、脚本家は考えずに記録した判断を返すので、同じ試合になります。ブラウザ版は Python の準備を含めて20秒ほど）。
    公開ログの照合値が合わなければ（作ったときとエンジンの版が違う）、知らせます。
  - **長い URL（`#r=`、約1万文字）**: 盤面の記録をそのまま入れたもの。判断の記録の無いリプレイ（以前に書き出したファイルなど）を共有するときだけ使います。
- **途中から再開する URL（`?resume=`）**: ディスクのメニューの『この場面から再開する URL をコピー』、リプレイ表示中の『再開の URL』。開くとその場面までを作り直し、続きを普通の対戦として遊べます。
  リプレイ表示中の『ここから遊ぶ』は、その場で続きを始めます。再開した後の脚本家は本物の自動の脚本家が考えます
  （作り直した部分では考えていないので、細かい覚えは空のまま。ルールの処理には影響しません）。
  - 最後まで進んだ試合なら、どちらにも脚本の中身（非公開シート）が入ります。
  - 受け付けなかった操作（反則の置き方・使えない能力の宣言）も残り、リプレイのログに赤い行で出ます（公開ログには入りません）。書き出したファイルにも入ります。
- **シナリオ**: シナリオエディタの『プレイ用の URL をコピー』。`index.html?code=…` を開くと、新しいゲームの欄にコードが入ります。

## シナリオエディタ（自分のシナリオを作って遊ぶ）

最初のダイアログの「シナリオを作る」か、`editor.html`（サーバー版は `/editor.html`）で開きます。

- 非公開シートにあたる項目（題名・ループ数・日数・ルールY/X・登場人物と役職・初期エリア・転校生の登場日／神格の登場ループ・大物のテリトリー・事件と犯人・特殊ルール）を入力します。
  必要な役職の員数は、選んだルールから表示します。
- 入力すると、エンジンが検証します（`engine.scripts.report`。役職の員数・犯人の重複・キャラクターごとの制約・このエンジンで遊べない要素）。
  ブラウザ版は初回だけ Python の準備に数十秒かかります。
- 誤りが無ければ**シナリオのコード**（`s1.` で始まる60〜90文字ほど）ができます。『このシナリオで遊ぶ』で対戦の画面が開き、新しいゲームの欄にコードが入ります。
  コードは人に渡せます（対戦の画面の「新しいゲーム」→「シナリオのコード」に貼る）。コードには非公開シートの中身が入っているので、渡す相手には中身が分かります。
- 『このブラウザに保存』は localStorage に保存します（ほかの端末・ブラウザとは共有されません）。JSON の書き出し・読み込み、コードからの読み込みもできます。
- コードの形（`engine/scripts.py` の `encode`・`decode`）: ルール・役職・事件・エリアを決まった表の番号に、キャラクターをカード番号にしてバイト列に詰め、base64url にしたもの。
  サーバー版では `python ai_gm.py --code s1.…` でも遊べます。

## 8. やり直し・別の脚本・設定

- **やり直す**: 進行役（ターミナル2）を止め、`game_ai/` を消してから起動し直します
- **別の脚本で遊ぶ**: `--script` を変えます。同梱の8本は [README](../README.md#遊べる脚本)、sangeki-scripts を隣に置けば `designed/d16` など
- **脚本を伏せて遊ぶ**: `--blind`（おすすめの脚本から遊んだことのないものを選び、遊び尽くしたら sangeki-scripts の自動生成の脚本から選びます）
- **相手の強さ**: `--mm calcG`（強い）・`searchL`・`search`（既定）
- **ポート**: サーバーの `PORT` を変えたら、ブラウザの URL も合わせます。手動モード（`node server.mjs` だけ）は既定で 8765・`game/`

## 9. 困ったとき

| 症状 | 確かめること |
|---|---|
| 盤面が「状態を読み込み中…」のまま | 進行役（`ai_gm.py`）が動いているか。`SANGEKI_GAME` と `--dir` が同じ場所か |
| 送信すると「送信に失敗しました」 | サーバー（`node server.mjs`）が動いているか |
| 画像が出ない・文字だけ | `bash setup_images.sh` を実行したか（`assets/tragedy_commons_5th` があるか） |
| 長く待っても進まない | 帯の「いま何を待っているか」を確認。脚本家の計算中ならターミナル2が動いています。エラーが出ていたら Issue へ |
| 前の試合の内容が残っている | `game_ai/` を消してから起動し直す |

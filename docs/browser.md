# ブラウザ対戦ツール（対AIモード）の使い方

ブラウザの盤面で **主人公3人（A・B・C）を1人で操作し、自動の脚本家と対戦** します。
ルールの処理（行動の解決・能力・事件・ループの終わり）はエンジンが行い、画面には公開情報だけが出ます。

> ルールそのものの説明は含みません。惨劇RoopeR のルールを知っている前提です。

## 1. 起動

準備（[README の「インストール」](../README.md#インストール)）が済んでいれば、ターミナルを2つ使います。どちらもリポジトリの根で実行します。

**いちばん簡単な起動（開始画面つき）**: ターミナル1つで、サーバーが進行役も起動します。

```bash
SANGEKI_AI=1 SANGEKI_PYTHON=.venv/bin/python SANGEKI_GAME=game_ai PORT=8766 node server.mjs
```

ブラウザで **http://localhost:8766/** を開くと、まずタイトル・免責事項・遊び方の案内が出ます。『ゲームを始める』で「新しいゲーム」の画面になり、
脚本・脚本家・乱数の種を選んで『開始』（試合の途中なら『続きから遊ぶ』で戻れます）。
既定は **脚本を伏せて遊ぶ**（自動生成の脚本から、遊んだことのない組を選ぶ）と、**いちばん強い脚本家 `calcG`** です。
試合の途中や終わった後も、帯の ⚙ →『新しいゲーム…』（終わった後は帯の『新しいゲーム』）で始め直せます。

- 脚本の一覧は、同梱の脚本と（sangeki-scripts があれば）設計した脚本です。題名は内容の手がかりになることがあるので、何も知らずに遊ぶなら「脚本を伏せて選ぶ」を使います（sangeki-scripts の自動生成の脚本から選ぶ）
- 開始画面で選べる脚本家は `calcG`（既定・最強・1手に数十秒）・`searchL`・`search`（速い）・`route`（最速）
- 脚本を一覧から選ぶこともできますが、**脚本のタイトルから脚本の内容が分かる可能性があります**
- 伏せて遊ぶには sangeki-scripts（自動生成の脚本）が必要です。無いときは一覧から選びます
- `?ux=off` では案内を出さず、すぐ「新しいゲーム」の画面になります
- `SANGEKI_PYTHON` は Python の場所（仮想環境の python。省くと `python3`）

**進行役を自分で起動する場合**（ほかの脚本家の型を使う、など）: ターミナルを2つ使います。

```bash
# ターミナル1: 盤面のサーバー
SANGEKI_GAME=game_ai PORT=8766 node server.mjs

# ターミナル2: 進行役（エンジンと自動の脚本家）
python ai_gm.py --script s03_bomb --mm calcG --seed 1
```

ブラウザで **http://localhost:8766/** を開きます。

- `SANGEKI_GAME` と `ai_gm.py --dir`（既定 `game_ai/`）は同じ場所を指すようにします。盤面と進行役はこの置き場所のファイル
  （`state.json`・`log.jsonl`・`inbox.jsonl`）でやりとりします
- サーバーは自分の PC の中だけで動きます（既定で `127.0.0.1`）。他の端末から開くときは `HOST=0.0.0.0` を付けます（信頼できるネットワークでだけ）
- 進行役のオプション: `--script`（脚本）、`--mm`（自動の脚本家）、`--seed`（乱数の種）、`--blind`（脚本を伏せて選ぶ。sangeki-scripts が必要）

### ブラウザだけで動かす版（Pyodide、試作）

Python（エンジンと自動の脚本家）をブラウザの中で動かす版です。サーバーは静的なファイルを配るだけで済みます（GitHub Pages などに置ける）。
盤面はサーバー版と同じ `board.html` を使い、サーバーへの要求をブラウザの中で答える小さなスクリプト（`web/shim.js`）を差し込みます。

```bash
bash web/build.sh                      # web/dist に組み立てる（画像は assets/ があれば写す。--no-img で写さない）
cd web/dist && python3 -m http.server 8784
# → http://localhost:8784/
```

- Python は [Pyodide](https://pyodide.org/)（v314.0.7、CDN から読み込む。初回は約30MB）。人の操作を待つところに JSPI を使うので、**Chrome・Edge の最近の版**で動きます（Firefox・Safari は未対応の見込み）
- 自動の脚本家の計算はブラウザを動かしている PC で行うので、速さは PC の性能に左右されます。脚本家の種類によっては手の計算で待たされます（calcG の1日目の伏せ札は、手元の計測で約25秒でした）
- CDN に届かない環境では `PYODIDE_DIR=<npm の pyodide パッケージ> bash web/build.sh --local-pyodide` で同梱し、`?pyodide=local` を付けて開きます
- 盤面の状態・ログはブラウザのメモリの中だけにあります（再読み込みすると試合は消えます）。推理シートの書き込みはブラウザに保存されます

## 2. 画面の見方

```
┌──────────────────────────── 帯 ─────────────────────────────┐
│ ループ 1/3  日 1/6  [フェイズ]  リーダー A  いま何を待っているか │
├──────────────────────────────┬──────────────────────────────┤
│                              │ ログ                          │
│   盤面（病院・神社・都市・学校）│ 操作（送信待ち・脚本家の返答・  │
│   キャラクター駒・カウンター・  │       友好能力・手札・事件予定） │
│   伏せ札・置いた札             │ 推理（公開シート・マトリクス…）  │
└──────────────────────────────┴──────────────────────────────┘
```

**帯**: ループと日、いまのフェイズ、リーダー、**いま誰の入力を待っているか**。使える友好能力があると件数のバッジが出ます。

**盤面**
- 4つのエリアのボードと、キャラクターの駒。駒の数字は `不` 不安・`友` 友好・`暗` 暗躍・`護` 護衛。**赤枠は不安臨界以上**
- ボードの左右の丸は、そのエリアの暗躍
- 脚本家の伏せ札は裏向きで置かれます。行動の解決で表になります
- 自分が置いた札は、送る前は点線の枠、送った後はフェイズが進むまで盤面に残ります

**右の欄**（見出しを押すと畳めます。畳むと盤面が広くなります）

| 欄 | 中身 |
|---|---|
| ログ | エンジンが処理した出来事（公開情報だけ）。役職などの理由は伏せられます |
| 操作 › 今日の出来事 | その日に起きたこと |
| 操作 › 送信待ち | 置こうとしている札・宣言。『確定して送る』で送信 |
| 操作 › 脚本家の返答 | 送った操作への返答（能力の解決・拒否など） |
| 操作 › 友好能力 | 宣言できる能力の一覧（使えるものが上に緑で並ぶ） |
| 操作 › 手札 | 主人公ごとの手札。★は1ループ1回の札で、使うと灰色 |
| 操作 › 事件予定 | 事件の日と名前、起きたか |
| 推理 | 自分用の推理シート（[5](#5-推理の欄)） |

## 3. 1日の流れと操作

帯の「いま何を待っているか」に従って進めます。自分の番でないときは、脚本家とエンジンの処理を待ちます
（`calcG` は1手に数十秒〜1分かかります）。

### ① 脚本家が伏せ札を置く

待つだけです。終わると帯に「行動カードを3枚（A→B→C）置いて『確定』。脚本家の伏せ札は 〇〇・〇〇・〇〇」と出ます。

### ② 主人公の札を置く

1. 置きたい **キャラクターかエリアを右クリック**
2. 「主人公A が札を置く…」→ 札を選ぶ（★は1ループ1回の札）
3. B・C も同じように置く → 「送信待ち」に3枚並ぶ
4. **『確定して送る』**

- **取り消し（送る前だけ）**: 送信待ちの行の × で1枚ずつ消す、『取り消す』で全部消す、同じ主人公でもう一度置くと置き直し（上書き）。
  手札の札を選んだ状態は Esc かもう一度クリックで解除。『確定して送る』の後は取り消せません
- 置き方の誤り（同じ対象に2人など）は画面では止めません。エンジンが判定し、反則ならログに理由が出ます

### ③ 行動の解決

自動です。6枚すべてが公開され、カウンターや移動がログと盤面に反映されます。

### ④ 脚本家能力フェイズ

自動です。脚本家の能力（ミスリーダーなど）の結果が「どこからともなく〇〇に不安+1」のようにログに出ます。

### ⑤ 主人公能力フェイズ（友好能力）

帯が「リーダーから友好能力を宣言」になります。

1. 「友好能力」の欄の **『宣言』** を押す（またはキャラクターを右クリック →「友好能力 …」）
2. 対象や選択肢を選ぶ（ルールXの宣言、事件の選択、カウンターの移し先など、能力ごとに聞かれます）
3. 1件ずつその場で解決されます。脚本家が拒否した場合も「脚本家の返答」とログに出ます
4. 宣言し終えたら、「送信待ち」の欄に出るボタン **『能力の宣言を終える』**（押すとすぐ送信されます）

- 同じ能力は1日1回、★は1ループ1回。友好が足りない能力は灰色ですが、宣言は止めません（エンジンが判定します）

### ⑥ 事件・ターン終了

自動です。事件の発生・不発、死亡、ループの終わりがログに出ます。翌日は①から。ループが終わると、次のループの準備も自動で進みます。

## 4. 最後の戦い

最終ループを落とすと（脚本によっては）最後の戦いに入ります。

1. **キャラクターを右クリック →「役職を指摘する（最後の戦い）…」→ 役職** を選んで送る
2. 1人ずつ、宣言した順に判定されます。外れた時点で脚本家の勝ちです
3. 全員を指摘したら、「送信待ち」の欄の **『指摘を終える』**

ゲームが終わると、**非公開シート**のダイアログが出ます。勝敗と決め手、脚本の題名、ルール、全員の役職（最後の戦いの指摘との答え合わせつき）、事件と犯人を表で見られます。閉じた後も帯の『非公開シート』で開き直せます。ログにも同じ内容が出ます。

## 5. 推理の欄

自分の推理を書き込むシートです。書いた内容は自動で保存され、再読み込みしても残ります（`game_ai/notes.json`）。

| 表 | 使い方 |
|---|---|
| 公開シート | 脚本の公開情報（惨劇セット・ループ数・日数・事件予定・特別ルール） |
| ルール | ルールX・Y ごとに「不明・候補・消えた・確定」の印を付ける |
| マトリクス | ルールと役職の員数の対応 |
| 役職の能力 | 早見表の役職の能力 |
| 敗北条件 | 主人公の負け方の一覧。ループごとに起きたかを付ける |
| 事件 | 事件ごとに犯人の推測を書く |
| 登場人物 | キャラクターごとの役職の推測とメモ |

**エンジンの候補**: 推理の欄の見出しにある『エンジンの候補』を押すと、公開された出来事からルール上ありうる組み合わせを数えた割合が重なります
（確定＝緑、強い候補＝橙、消えた＝灰の取り消し線）。「狙い込み」は、脚本家が伏せ札を置いた場所から狙いを読んだ見込みです。
**答えを自分で考えたいときは押さないでください。**

## 6. 便利な操作

- **クリックで置く**: 手札の札をクリックしてから、キャラクターかエリアをクリック（タップ・Enter でも可、Esc で解除）。スマホ・タブレットでも使えます
- **過去の盤面**: ログの行の右端の『盤面』ボタンで、その時点の盤面を表示します。帯の『いまに戻る』で戻ります
- 「脚本家に伝える」の欄・「ハッシュでの固定」の欄・ログの行の右クリック →「異議を送る」は、人が進行役を務める手動モード用です。対AIモードでは表示しません

## 7. 表示の設定（場面カード・考え中・画像なし）

人が遊びやすいように、次の表示があります。帯の右端の **⚙** で個別に切り替えられます（設定はこのブラウザに保存）。

| 表示 | 中身 |
|---|---|
| **考え中** | 脚本家が考えている間、画面の中央に「脚本家が考えています（伏せ札）」・経過秒数・進み具合のバー・いまの段階（例: 伏せ札の置き場所を比べています（5/47 組）、負け筋を逆算しています）を出します。進み具合が分からない処理（能力・事件の選択、送信の直後、ゲームの準備）は流れる帯で示します。盤面とログはそのまま見られ、操作もできます |
| **自分の番** | 入力が要るとき、帯が緑になり、ブラウザのタブの題名が「★あなたの番」になります（別のタブを見ていても気づける） |
| **場面カード** | フェイズごとに、そのフェイズで起きたこと（脚本家の伏せ札の置き場所、公開された札、移動、カウンター、事件、死亡）を1枚のカードにまとめて出します。何も起きなかったフェイズも「特に何も起きなかった」と出します（自分が入力するフェイズを除く）。数秒で自動で閉じます。自分の番の直前の1枚は、閉じるまで残ります（見落とし防止） |
| **日の終わり** | 1日が終わると「○日目の終わり」（ループの終わりは「ループ○の終わり」）のカードに、その日に起きたことをまとめて出します。**自動では閉じません**。『次の日へ』を押すまで次に進まないので、その日を振り返って考えられます（その間に脚本家は次の日を考えています） |
| **盤面を見る** | 場面カードを画面の下の細い帯に畳み、盤面をゆっくり確かめられます。『場面に戻る』で戻ります |
| **解決前／解決後** | その場面の処理の前と後の盤面を切り替えて見比べます。解決後では、変わったキャラクター（カウンター・移動・生死）を黄色の枠で強調します。帯の『いまに戻る』で今の盤面に戻ります |
| **キャラクターの説明** | キャラクターにマウスを乗せると、大きめの説明（不安臨界・カウンター・初期エリア・禁止エリア・属性・特性・友好能力）を出します |
| **画像なしの表示** | 盤面の画像が読めないとき（`setup_images.sh` を実行していないなど）は、自動で文字の表示になります。エリアは色分けしたパネル、キャラクターは名前の札、行動カードは短い名前の札（例: 暗+2・不−1・移↕、伏せ札は「伏」）。スマホでも名前が読めます |

⚙ の設定:

| 設定 | 選べる値 |
|---|---|
| 場面カード | 出す／出さない |
| 演出の速さ | ゆっくり・ふつう・速い・なし |
| 自動で閉じる | 秒数（0 で自動では閉じない） |
| 考え中の表示 | 出す／出さない |
| 画像 | 自動・あり・なし（文字） |

**URL での指定**（保存した設定より優先し、そのページだけ効きます）:

| URL | 効果 |
|---|---|
| `http://localhost:8766/?ux=off` | 場面カード・演出・考え中の表示をすべて切る（自動の試験や、素早い確認用） |
| `?ux=fast` | 演出を速くする |
| `?img=off` | 画像なしの表示にする（`?img=on` で画像あり） |

サーバーを `SANGEKI_NOIMG=1` を付けて起動すると、画像を配信しないので、誰が開いても画像なしの表示になります。

## リプレイ（書き出しと読み込み）

試合の記録（公開ログ・場面ごとの盤面・終了時の盤面と非公開シート）を JSON ファイルに書き出し、あとで読み込んで見返せます。
エンジンは使わず記録を順に表示するだけなので、サーバー版でもブラウザ版でも同じように動き、すぐ開けます。

- **書き出す**: ⚙ →『リプレイを書き出す』、またはゲーム終了の非公開シートの『リプレイを保存』。試合の途中でも書き出せます（そのときは脚本の中身を含みません）
- **読み込む**: ⚙ →『リプレイを読み込む…』でファイルを選ぶ。画面の下に操作バーが出ます（⏮ 最初へ・◀ 1つ戻る・▶ 再生／停止・▶| 1つ進む・⏭ 最後へ・スライダー）。
  各場面の盤面と、そこまでのログを表示し、その場面で起きた行を青く強調します。終わった試合なら『非公開シート』も開けます
- **URL で開く**: `?replay=<リプレイの JSON の URL>` を付けて開くと、そのリプレイを表示します（人に見せるとき）
- 『リプレイを終える』で、いまの試合の表示に戻ります（リプレイを見ている間も試合は続いています）

## URL での共有

- **リプレイ**: ⚙ の『リプレイの URL をコピー』、終了時の非公開シートの『リプレイの URL をコピー』、リプレイ表示中の『URL をコピー』。
  盤面の記録を前の場面からの差分にして圧縮し、URL の `#r=` の後ろに入れます（1試合で約1万文字。`#` の後ろはサーバーに送られません）。
  最後まで進んだ試合なら、脚本の中身（非公開シート）も入ります。
- **シナリオ**: シナリオエディタの『プレイ用の URL をコピー』。`index.html?code=…` を開くと、新しいゲームの欄にコードが入ります。

## シナリオエディタ（自分のシナリオを作って遊ぶ）

最初のダイアログの「シナリオを作る」か、`editor.html`（サーバー版は `/editor.html`）で開きます。

- 非公開シートにあたる項目（題名・ループ数・日数・ルールY/X・登場人物と役職・初期エリア・転校生の登場日／神格の登場ループ・大物のテリトリー・事件と犯人・特殊ルール）を入力します。
  必要な役職の員数は、選んだルールから表示します。
- 入力すると、エンジンが検証します（`engine.scripts.report`。役職の員数・犯人の重複・キャラクターごとの制約・このエンジンで遊べない要素）。
  ブラウザ版は初回だけ Python の準備に数十秒かかります。
- 誤りが無ければ**シナリオのコード**（`s1.` で始まる60〜90文字ほど）ができます。『このシナリオで遊ぶ』で対戦の画面が開き、新しいゲームの欄にコードが入ります。
  コードは人に渡せます（対戦の画面の「新しいゲーム」→「シナリオのコード」に貼る）。コードには非公開シートの中身が入っているので、渡す相手には中身が分かります。
- 『このブラウザに保存』は localStorage に保存します（ほかの端末・ブラウザとは共有されません）。JSON の書き出し・読み込み、コードからの読み込みもできます。
- コードの形（`engine/scripts.py` の `encode`・`decode`）: ルール・役職・事件・エリアを決まった表の番号に、キャラクターをカード番号にしてバイト列に詰め、base64url にしたもの。
  サーバー版では `python ai_gm.py --code s1.…` でも遊べます。

## 8. やり直し・別の脚本・設定

- **やり直す**: 進行役（ターミナル2）を止め、`game_ai/` を消してから起動し直します
- **別の脚本で遊ぶ**: `--script` を変えます。同梱の8本は [README](../README.md#遊べる脚本)、sangeki-scripts を隣に置けば `designed/d16` など
- **脚本を伏せて遊ぶ**: `--blind`（sangeki-scripts の自動生成の脚本から、遊んだことのない組を選びます）
- **相手の強さ**: `--mm calcG`（強い）・`searchL`・`search`（既定）
- **ポート**: サーバーの `PORT` を変えたら、ブラウザの URL も合わせます。手動モード（`node server.mjs` だけ）は既定で 8765・`game/`

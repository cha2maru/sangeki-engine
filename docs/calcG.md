# 脚本家 calcG の仕組み

`calcG` は、このリポジトリで現在いちばん強い自動の脚本家です。
**「探索」で候補の手を比べる層** の上に、**「負け筋の逆算」で、そのループを取れるかを計算する層** を重ねています。

```
calcG = searchL（探索）
      ＋ 逆算（必ず取れるループは、その手順を最優先）
      ＋ 確定したループは押さずに隠す
      ＋ 伏せ札の二択の賭け（取れる確率 0.5 以上なら）
```

コードは `selfplay/search_mm.py`（`SearchMastermind`）と `engine/route_calc.py`、組み立ては `selfplay/league.py` の `make('calcG')` です。

## 1. 何を決めるか

| 判断 | 関数 | 中身 |
|---|---|---|
| 伏せ札3枚 | `mm_cards` | この文書の大半。毎日いちばん重い判断 |
| 脚本家能力（ミスリーダー・クロマクなど） | `mm_ability` | 進みと情報の漏れで選ぶ（[6](#6-伏せ札以外の判断)） |
| 事件の効果の対象 | `incident_choice` | 負け筋がいちばん近づく対象 |
| 友好能力の拒否 | `refuse` | 任意で拒否できる役職のとき、拒否で漏れる情報が小さければ拒否する |
| ループの準備（手先・学者など） | `loop_setup` | 負け筋の評価で選ぶ。脚本ごとの指針があればそれに従う |
| キラーなどの任意能力 | `killer_pick` | 基本の脚本家の判断（負け筋が進むなら使う） |

主人公の札は見えません。見えるのは、主人公と同じ**公開情報**（盤面・公開された札・ログ）と、自分の脚本です。

## 2. 1手の決め方（全体の流れ）

伏せ札は、次の**優先順**で決めます。上の段で決まれば、下の段は見ません（点数を足し合わせて混ぜることはしません）。

```
① このループはもう取ったか（確定）？
     はい → 隠す: 友好の閾値に一番近い情報・守りの能力の持ち主に友好禁止。残りの枠は「押さない札」で埋める
② 主人公が伏せ札を知っていて最善に止めても、このループを必ず取れるか？
     はい → その手順の今日の札を置き、残りの枠を探索の手で埋める
③ 伏せ札の中身が見えないことを使った「今日の賭け」で、取れる確率が 0.5 以上か？
     はい → 賭けの混ぜ方から1つ引いて置く（暗躍+2 は見張られていない側へ）
④ どれでもない → 探索でいちばん評価の高い手
```

脚本家にとって「ループを取る」ことが常に最優先で、情報を隠すなどはその次、という考えをそのまま順番にしています。

## 3. 探索の層

`searchL` に当たる部分です。①〜③に当てはまらないときは、この層が手を決めます。①〜③に当てはまるときも、残りの枠を埋めるのに使います。

### 候補の手を作る

- **置き場所の3つ組**: 負け筋に関わる人物・ボードを中心に、置き場所の組を8つ選び（`triples`）、それぞれに札の割り当てをいくつか作る（`cards`）
- **定石の手を必ず入れる**（`joseki`）: 「二枚押し」＝暗躍+2 と暗躍+1 を別々の負け筋に同時に置く（主人公の暗躍禁止は1日1か所しか効かないので、どちらかが通る）
- **閾値の前日の友好禁止**（`gwx_eve`）: 主人公が今日の友好+1/+2 で情報・守りの能力に届く人物がいれば、そこに友好禁止を置く手

### 主人公の応手を予想する

脚本家の中に **主人公の模型**（公開情報だけで推理する主人公 `ReadingBlocker`、想定する世界16個）を持ち、
「この置き場所なら主人公はこう止める」を予想します（`opp=16`）。主人公には置き場所しか見えないので、応手は置き場所の組で決まります。

### 手を評価する

候補の手と予想した応手をエンジンで実際に解決し、さらに **その日の脚本家能力フェイズと事件まで進めた盤面**（`lookday`）を評価します。

- **負け筋の近さ**: `Σ 1/(1+距離)`（`engine/routes.py` が列挙する、主人公が負ける道筋ごとの「あと何が足りないか」）。
  本命1本だけでなく、複数の筋を同時に進める手を好みます
- **消しにくい暗躍**（`persist`）: 暗躍は主人公が取り除きにくいので、暗躍の条件をすでに満たした筋に加点
- 補正: 1ループ1回の札の温存（`hold`）、今日置かないと締め切りに間に合わない札（`urgency`）、ループ1の押し切り（`early`）、
  止められ続けている所にまた置く手の減点（`stuck`）、確定後に事件の犯人を自分で冷ます手の減点（`hide_culprit`、犯人を教えるため）

## 4. 逆算の層

`engine/route_calc.py` です。盤面を、負け筋のカウンター（不安・暗躍）だけを取り出した**小さな盤面**に抽象化し、
残りの日を後ろ向きに計算します。探索のように手を試すのではなく、**脚本が決まっていれば「取れるかどうか」は計算で出る**、という考えです。

### 抽象化

- **対象**: 負け筋の条件に出るカウンター（人物の不安・暗躍、ボードの暗躍）。最大5つ
- **負け筋**: 対象ごとの必要量の組（どれか1本の筋の条件が全部そろえば負け）。判定の時は筋ごとに違う
  - 役職のターン終了の筋（メインラバーズなど）: 毎日
  - 事件の筋: その事件の日
  - ルールYのループ終了時の筋（時限爆弾・契約など）: 最終日
- **脚本家の札**: 不安+1 は2枚、暗躍+1 は1枚、暗躍+2 はループに1回、不安禁止。1日3枚、同じ対象に1枚
- **主人公の札**: 不安−1 は各主人公ループに1回、暗躍禁止は1日1か所だけ効く。各主人公1日1枚、同じ対象に2人は置けない

### 2つの判定

- **forced（必ず取れる）**: 主人公が**伏せ札の中身を知っていて最善に止めても**、脚本家が取れるか。後ろ向きの動的計画法（DP）で解きます
- **locked（確定）**: 脚本家が残りの日に**何もしなくても**取れるか

forced と locked を分けるのが大事です。「今日は置かなくても明日置けば取れる」局面（forced だが locked でない）を確定と取り違えると、
押すのをやめて取り逃がします。forced のときは、取れる手が複数あれば**押す札の多い手**を選びます（数えていない主人公の能力への余裕）。

### 数えていないもの

| 数えないもの | 影響 |
|---|---|
| キャラクターの能力（護衛・蘇生・カウンターの除去など） | 主人公の守りを数えないので、「取れる」が甘く出ることがある。探索の層や実際の解決で補う |
| 移動 | 位置の条件は「今そろっていればそのまま」とみなす。主人公の移動で崩れる筋がある |
| 事件でボードに暗躍を置く筋、脚本家能力による補給 | 脚本家の味方を数えないので、「取れない」が辛く出る |

## 5. 伏せ札の二択の賭け

逆算の DP は「主人公が伏せ札の中身を知っている」前提です。実際の主人公には **置き場所しか見えません**。
これを使うのが「今日の賭け」（`route_calc.solve_hidden`）です。

- 置き場所の組（3か所）ごとに、**札の割り当て（脚本家）× 応手（主人公）** の表を作ります。
  値は「今日の後で、脚本家が必ず取れる盤面（forced）になるなら 1、ならないなら 0」
- 主人公は置き場所を見てから応手を選べますが、中身は見えません。これを**同時手番の行列ゲーム**として線形計画（LP）で解き、
  脚本家が混ぜ方を工夫したときに取れる確率と、その混ぜ方を出します
- 効果の無い札（友好禁止など）も「見せ札」として割り当ての候補に入ります

**例**（d16 の1日目）: 都市（爆弾）と従者・幻想（遠隔殺人の標的）の両方が「暗躍2で負け」。
暗躍+2 と暗躍+1 を別々に置けば、暗躍禁止は1か所しか効かないので、主人公がどちらを止めても5割で片方が通る、と出ます。

**見張り**: 同じ確率の混ぜ方が複数あるときは、暗躍+2 を**主人公に見張られていない側**に置きます。
見張りの度合いは公開情報から数えます（主人公が暗躍禁止を置いた回数、前のループで暗躍が2に届いて筋が割れた所）。
ループ2以降に割れた筋（例: 爆弾の都市）にはおとりの暗躍+1、割れていない筋に暗躍+2、という形になります。

制限: 賭けは**1日分だけ**です（何日も続けて賭ける値、たとえば暗躍+2 を温存して後日に賭ける価値は数えません）。
位置の条件を含む筋は、主人公の移動で崩されるので賭けには数えません。

## 6. 伏せ札以外の判断

- **脚本家能力**: 使う・使わない・対象を「負け筋の進み − λ × 漏れる情報」で選びます。漏れる情報は、脚本家が手元に持つ
  公開情報の推理に、その能力で生じる観測を試しに足したときの、役職の不確かさの減り（ビット）です。
  λ は最終ループで半分にします（取らないと負けなので進みを重く見る）
- **事件の対象**: 負け筋の評価がいちばん上がる対象
- **友好能力の拒否**: 任意で拒否できる役職（キラー・クロマク・ファクター）のときだけ考えます。役職を明かす能力（サラリーマン・巫女）は拒否し、
  それ以外は「拒否した」という観測で漏れる情報が 0.5 ビット未満なら拒否します（友好無視を持つことが割れるため）

## 7. 型の組み立てとパラメータ

`make('calcG')` は次のように積み上がっています（`selfplay/league.py`）。

| 型 | 中身 |
|---|---|
| `searchP1` | 探索の基本＋主人公の模型（`opp=16`, `triples=8`）＋定石（`joseki`）＋消しにくい暗躍（`persist=1`）＋閾値前日の友好禁止（`gwx_eve=1`）＋確定後に犯人を冷まさない（`hide_culprit=1`） |
| `searchL` | `searchP1` ＋その日の能力・事件まで読む（`lookday`） |
| `calcL` | `searchL` ＋逆算（`calc`）＋確定後に隠す |
| `calcG` | `calcL` ＋今日の賭け（`gamble=0.5`） |

主なパラメータ（`SearchMastermind` の属性）:

| 名前 | 値 | 意味 |
|---|---|---|
| `lam` | 0.1 | 情報の漏れの重み λ |
| `hold` | 0.25 | 1ループ1回の札を使う手の減点 |
| `urgency` | 1.0 | 締め切りに間に合わない札の加点 |
| `early` | 2.0 | ループ1の押し切りの加点の倍率 |
| `stuck` | 0.3 | 止められ続けている所にまた置く減点 |
| `persist` | 1.0 | 消しにくい暗躍の加点 |
| `gwx_eve` | 1.0 | 閾値の前日の友好禁止の加点 |
| `hide_culprit` | 1.0 | 確定後に犯人を冷ます手の減点 |
| `calc` | True | 逆算の層を使う |
| `gamble` | 0.5 | 賭けに出る確率のしきい値（0 で使わない） |

重みは次の一手問題で自動調整できます（[research.md の「重みの自動調整」](research.md#5-重みの自動調整tune)）。

## 8. 強さの記録

- **脚本家の次の一手問題**（40問）: `searchL` 14 → 逆算を入れた `calcL` 18 → 確定後に隠す 25 → 賭けを入れた `calcG` **27**（悪化した問題なし）
- **脚本を知らない AI エージェント（主人公）との対戦**（designed/d16、2試合）: どちらの試合も脚本家が全3ループを取り、最後の戦いまでもつれました
  （1試合は主人公が全員正解、1試合は脚本家の勝ち）。同じ条件で `searchL` はループ3を主人公に取られていました

## 9. 弱点と今後

対戦相手（主人公）からの指摘と、計算の限界です。

- **確定が読まれる**: ループの勝ちが確定した瞬間に押さない札だけになるので、主人公に「もう決まった」と読まれます（自分の事件の犯人に不安−1 など）。
  確定の前後で札の性質を平らにするのが課題です
- **要らない能力で役職が割れる**: 勝ちに要らない脚本家能力を使って、役職を明かしてしまうことがあります（ミスリーダー2人の同時使用でコピーキャットが割れた）
- **効果の無い札・同じ手の繰り返し**: 空のボードへの移動、禁止エリアへの移動、毎ループ同じ脅威に同じ札、など
- **逆算が数えないもの**: 能力・移動（[4](#数えていないもの)）。賭けは1日分だけ
- **重い**: 1手の平均は数秒、ループの初日は数十秒かかることがあります

## 10. 試してみる

```python
import random
from engine.scripts import by_id
from engine.route_calc import forced_plan
from selfplay.league import make

sc = by_id('s03_bomb')
mm = make('calcG', random.Random(1), sc)       # 自動の脚本家
# 対戦の途中の盤面 s で:
#   forced_plan(s, sc['days'], hidden=True) → {'forced', 'move', 'locked', 'p', 'mix', 'routes'}
#   mm.mm_cards(s) → 今日の伏せ札3枚
```

ブラウザで対戦するときは `python ai_gm.py --mm calcG`、自動どうしなら `python -m selfplay.league --pairs calcG:tuned-pc_r2 …` です。

# CLI対戦ツール（play_cli）の使い方

ターミナル上で **主人公（または脚本家）を操作し、自動プレイヤーと対戦** するための道具です。
ブラウザ版（[browser.md](browser.md)）と異なり、GUIサーバーを使わずターミナルのみで動作します。

> ルールそのものの説明は含みません。惨劇RoopeR の基本ルールを知っている前提です。

コードは `selfplay/play_cli.py` にあります。

## 1. 起動と対戦の仕組み

`play_cli` は既定では常駐して入力を待つ形式ではなく、**「乱数の種（seed）」＋「これまでの選択の一覧（ファイル）」から毎回最初からシミュレーションを再生する** 仕組みです（再生方式）。
主人公側には、試合を1回だけ進めて入力を待ち続ける **常駐の郵便受けモード（`--serve`）** もあります（[8章](#8-常駐の郵便受けモード--serve)）。決定ファイルの形は両方で同じです。

```
[CLI実行] → [ファイルから過去の選択を再生] → [プレイヤーの手番で停止・盤面表示]
   ↑                                                           ↓
   └──────────── [ファイルに次の1手を追記] ◀────────────────────┘
```

プレイヤーの番に達すると、現在の盤面と選べる手・前の自分の決定から後の出来事を表示してプログラムが終了します。プレイヤーは表示を見て次の手を決め、指定したファイルに1行（JSON）追記して再実行します。これをゲーム終了まで繰り返します。

---

## 2. コマンドの書式と引数

リポジトリ直下の `play` ディレクトリで実行します。

```bash
cd play && python3 -m selfplay.play_cli --side pc --opp calcG --script s03_bomb --seed 1 --file my_game.jsonl
```

### 主な引数

| 引数 | 既定値 | 説明 |
|---|---|---|
| `--side` | `mm` | プレイヤーの担当陣営。`pc`（主人公）または `mm`（脚本家）。`both` はエージェント同士の対戦用 |
| `--opp` | 自動 | 相手のAIの型。主人公側なら相手脚本家（`calcG`, `searchL`, `route` など）。脚本家側なら相手主人公（`readlook`, `read`, `blind` など） |
| `--script` | `s03_bomb` | 使用する脚本ID（`engine/scripts/<id>.json`）。同梱の脚本や設計した脚本を指定 |
| `--seed` | `5` | 乱数の種。ゲーム展開を決定論的に再現するために固定 |
| `--script-file` | なし | 脚本IDをファイルから読む（`--script` の代わり）。IDは画面に出さない。目隠しの対戦用 |
| `--file` | なし | プレイヤーの決定を1行ずつ記録するファイルパス（JSON Lines形式） |
| `--serve` | なし | 常駐の郵便受けモード。`--side pc` と `--file` が必要（[8章](#8-常駐の郵便受けモード--serve)） |

試合の条件（`script`・`seed`・`side`・`opp`）は、初回に決定ファイルの横の `<file>.meta.json` に残ります。
以後、違う条件で同じ決定ファイルを使おうとすると「試合の条件が … と違う」と出て止まります
（同じ種類の決定が並んでいると、条件を間違えても黙って別の試合として再生されてしまうため）。

## 3. ゲームの流れ（1手の進め方）

1. **初回実行**: 決定ファイル（例: `my_game.jsonl`）が空、または存在しない状態でコマンドを実行します。
2. **盤面確認**: ターミナルに現在のループ・日数・盤面状況・脚本家の伏せ札の位置などが表示されます。
3. **決定の記録**: 画面の案内に従い、次の行動を1行のJSONとして `my_game.jsonl` の末尾に追記します。
4. **再実行**: 同じコマンドを再度実行します。追記した手が反映され、次の判断フェイズ（能力宣言や翌日の手番など）まで進みます。
5. **決着**: ループを重ねて情報を集め、最終日を耐え抜くか、最終ループの「最後の戦い」で役職を当てることで勝利となります。

## 4. 画面の見方

`--side pc`（主人公側）で実行した場合、役職などの非公開情報は伏せられ、公開情報のみが表示されます。

```text
=== Claude（主人公）の番: 行動カード（A→B→C）（ループ 1/3・1日目/6日、リーダー A）
  公開シート: Basic Tragedy X（ループ 3 回 × 6 日）
  C01 男子学生（臨界2） 学校 生 不0 友0 暗0 護0
  C02 女子学生（臨界3） 学校 生 不0 友0 暗0 護0
  C03 お嬢様（臨界1） 学校 生 不0 友0 暗0 護0
  ...
  ボードの暗躍 {'病院': 0, '神社': 0, '都市': 0, '学校': 0}  使用済み {'M': [], 'A': [], 'B': [], 'C': []}
  事件予定 [(2, '不安拡大'), (3, '邪気の汚染'), (5, '殺人事件')]  公開された役職 {}
  札のコード: PAR+ 不安+1 / PAR- 不安-1（ループ1回）/ GW1 友好+1 / GW2 友好+2（ループ1回）/ INTX 暗躍禁止 / MV_V 移動↑↓ / MV_H 移動←→ / MVX 移動禁止（ループ1回）。ボードは B:HOS・B:SHR・B:CIT・B:SCH
   {"脚本家の伏せ札の置き場所": ["C06", "B:SHR", "B:CIT"]}
  出来事（L1D1 actions）: 脚本家の札: サラリーマン=暗躍+1、神社=暗躍+1、都市=不安+1 ／ ...
```

* **タイトル行**: 現在のループ・日数・リーダー順（行動カードを置く順番。例: `A→B→C`）。
* **キャラクター表示**: 各キャラの現在位置、生死、不安（不）、友好（友）、暗躍（暗）、暗殺保護（護）。
* **ボードの暗躍**: 病院・神社・都市・学校に置かれている暗躍カウンター。
* **使用済み**: 各陣営がこのループですでに消費したループ1回制限カード。
* **事件予定**: どの日数に何の事件が計画されているか。
* **脚本家の伏せ札の置き場所**: 脚本家がカードを裏向きに配置した3箇所。
* **出来事**: 前の自分の決定から後に起きたことを全部（行動解決フェイズで表向きになった脚本家の札、発生した事件など）。
  主人公側では役職や理由は伏せ、対AIモードの公開ログと同じ文で出します。件数を絞りたいときは環境変数 `PLAY_CLI_LOG=8` のように直近の件数を指定します。
* **！行わなかった友好能力の宣言**: 同じ日にまとめて宣言した友好能力は1つずつ解決されるため、先の能力で状況が変わって合法でなくなった宣言は行われません。
  その場合は `！行わなかった友好能力の宣言（L1D3）: {...} … 理由` と表示されます（決定ファイルの行そのものは受け付け済みです）。

## 5. 入力フォーマット（決定の書き方）

`--file` に指定したファイルへ、手番の順に1行ずつJSONを追記します。

### 主人公側（`--side pc`）の決定

#### ① 行動カード配置 (`kind: "pc_cards"`)
リーダー順（例: A→B→C）で3人の主人公が置くカードを3枚指定します。
```json
{"kind": "pc_cards", "choice": [{"by": "A", "target": "C03", "card": "PAR-"}, {"by": "B", "target": "B:SHR", "card": "INTX"}, {"by": "C", "target": "C06", "card": "GW1"}]}
```
* **札のコード (`card`)**:
  * `PAR+`: 不安 +1
  * `PAR-`: 不安 -1（ループ1回制限）
  * `GW1` : 友好 +1
  * `GW2` : 友好 +2（ループ1回制限）
  * `INTX`: 暗躍禁止（対象の暗躍カウンター追加を無効化）
  * `MV_V`: 移動↑↓（病院 ⇄ 学校、神社 ⇄ 都市）
  * `MV_H`: 移動←→（病院 ⇄ 神社、学校 ⇄ 都市）
  * `MVX` : 移動禁止（ループ1回制限）
* **配置対象 (`target`)**:
  * 人物: `"C01"` 〜 `"C09"`（スクリプトに登場するキャラクターID）
  * ボード: `"B:HOS"`（病院）、`"B:SHR"`（神社）、`"B:CIT"`（都市）、`"B:SCH"`（学校）

#### ② 友好能力の宣言 (`kind: "abilities"`)
その日の夕方に友好能力を使うかどうかを指定します。
* **使わない場合**:
  ```json
  {"kind": "abilities", "choice": []}
  ```
* **使う場合**: `[キャラクターID, 能力番号, 引数]` の配列で指定します。
  ```json
  {"kind": "abilities", "choice": [["C06", 0, null], ["C08", 2, {"target": "C02", "mode": "remove"}]]}
  ```
  主な能力の引数の形式:
  * 情報屋 (`C07`): `{"declare": "X_..."}` （ルールXの推理・公開要求）
  * 医者 (`C08`): `{"target": "C02", "mode": "remove"}`
  * 委員長 (`C09`): `{"card": "PAR-"}`
  * 刑事 (`C05`): `{"incident": "MURDER", "day": 5}`

#### ③ 最後の戦い (`kind: "final"`)
全キャラクターの役職を宣言順に指定します。
```json
{"kind": "final", "choice": [{"char": "C01", "role": "PERSON"}, {"char": "C02", "role": "PERSON"}, {"char": "C03", "role": "PERSON"}, {"char": "C04", "role": "WITCH"}, {"char": "C05", "role": "FACTOR"}, {"char": "C06", "role": "PERSON"}, {"char": "C07", "role": "FRIEND"}, {"char": "C08", "role": "PERSON"}, {"char": "C09", "role": "PERSON"}]}
```

---

### （参考）脚本家側（`--side mm`）の決定

自分が脚本家としてプレイする場合のフォーマットです。

* **ループの準備**: `{"kind": "loop_setup", "choice": {"init": {"C18": "HOS"}}}`
* **伏せ札3枚**: `{"kind": "mm_cards", "choice": [{"target": "C03", "card": "INT1"}, {"target": "B:SHR", "card": "INT2"}, {"target": "C06", "card": "PAR1"}]}`
* **脚本家能力**: `{"kind": "mm_ability", "choice": "C03"}` または `null`
* **不穏な噂**: `{"kind": "rumor", "choice": "B:SHR"}` または `null`
* **事件の対象選択**: `{"kind": "incident", "choice": {"target": "C02"}}`
* **キラーの任意能力**: `{"kind": "killer", "choice": [{"char": "C08", "ability": "KILLER_KEY"}]}` または `[]`
* **友好能力の拒否**: `{"kind": "refuse", "choice": true}` または `false`

## 6. 脚本 s03_bomb で遊ぶ例

### 脚本の基本構成
* **タイトル**: 時限の魔女（試験用）
* **セット**: Basic Tragedy X（BTX）
* **ループ回数**: 3 回
* **日数**: 各ループ 6 日間
* **事件予定**:
  * 2日目: `不安拡大`（犯人: C03 お嬢様、不安臨界 1）
  * 3日目: `邪気の汚染`（犯人: C02 女子学生、不安臨界 3）
  * 5日目: `殺人事件`（犯人: C06 サラリーマン、不安臨界 2）

### 対戦相手 `calcG` の特徴
相手AIの `calcG` は、**「負け筋（惨劇）の逆算」** を行う強力な脚本家です。
* 時限爆弾（神社などの暗躍カウンター蓄積）を積極的に狙い、最短手数で爆破勝利を試みます。
* 主人公の暗躍禁止（`INTX`）が1日1箇所しか防げないことを利用し、二重の脅威を仕掛けてきます。

### 主人公側の対策
1. **臨界の管理**: 不安臨界が 1 と極めて低いお嬢様（`C03`）は、2日目の「不安拡大」のトリガーになりやすいため、早期に不安を下げるか見張ります。
2. **暗躍の阻止**: 神社などのボードに暗躍が集まり始めたら、`INTX` を置いて爆発を阻止します。
3. **能力の活用**: 友好度を上げて情報屋や刑事の能力を使い、ルールや犯人を暴いていきましょう。

## 7. 便利な使い方・注意点

* **巻き戻し（アンドゥ）**:
  決定履歴ファイル（`my_game.jsonl`）の末尾から行を削除してコマンドを再実行するだけで、任意の過去の手番まで簡単に巻き戻せます（再生方式のとき。常駐中は済んだ決定を戻せないので、止めてから行を削り、起動し直します）。
* **決定の番号**:
  行に `"n": 番号` を付けると、その番号の決定として読みます。付けない行は、それまでの最大の番号+1 です。同じ番号の行が複数あれば最後の行を使います。
  つまり、誤った行を消さなくても、同じ番号で正しい行を足せば上書きできます。
* **棋譜の保存・共有**:
  `my_game.jsonl` 自体が棋譜になっています。同じコマンドとシード値を使えば、誰でもまったく同じ盤面展開を完全に再現できます。
* **思考時間の目安**:
  `--opp calcG` は毎ターンの候補手を深く計算するため、1手あたりの計算に十数秒〜数十秒ほど要する場合があります。高速に対戦を試したい場合は `--opp route` や `--opp search` を指定すると軽快に動作します。
  再生方式では毎回最初から再生するので、重い相手ほど手数に比例して遅くなります。重い相手と1試合通すなら `--serve` を使います。

## 8. 常駐の郵便受けモード（--serve）

`--serve` を付けると、`play_cli` は終了せずに試合を1回だけ進めます（`--side pc` 専用）。
自分の番が来るたびに問いをファイルに書き、決定ファイルにその番の答えが1行足されるまで待ちます。
再生方式と違って毎回最初から考え直さないので、`calcG` のような重い相手でも1手ごとの待ち時間が増えません。
LLM のエージェント（Claude など）が、ファイルの読み書きだけで遊ぶための形です。

```bash
cd play && python -m selfplay.play_cli --side pc --opp route --seed 2 --script s03_bomb --file DIR/d.jsonl --serve
```

`DIR`（決定ファイルのあるディレクトリ）に、次のファイルができます。

| ファイル | 中身 |
|---|---|
| `DIR/question.txt` | いまの問い。1行目が JSON の見出し、2行目から盤面と「前の決定から後の出来事」。番が来るたびに丸ごと書き換わる |
| `DIR/d.jsonl` | 自分の決定（答える側が1行ずつ足す）。形は再生方式と同じ |
| `DIR/d.jsonl.meta.json` | 試合の条件（script・seed・side・opp） |
| `DIR/public_log.txt` | 公開ログ。自分の決定と出来事を随時追記する |
| `DIR/result.txt` | 終局で書く。結果と全公開ログ |

### 問いの形（question.txt）

1行目の見出しで、何番目のどの種類の決定を求めているかが分かります。

```text
{"n": 1, "kind": "pc_cards"}
=== Claude（主人公）の番: 行動カード（A→B→C）（ループ 1/3・1日目/6日、リーダー A）
  公開シート: Basic Tragedy X（ループ 3 回 × 6 日）
  C01 男子学生（臨界2） 学校 生 不0 友0 暗0 護0
  ...
   {"脚本家の伏せ札の置き場所": ["C07", "B:SHR", "B:SCH"]}
前の決定から後の出来事:
```

### 答え方

決定ファイルに1行足します。書式は[5章](#5-入力フォーマット決定の書き方)と同じで、`"n"` を付けると番号を明示できます（付けなければ最大の番号+1）。

```json
{"n": 1, "kind": "pc_cards", "choice": [{"by": "A", "target": "C03", "card": "PAR-"}, {"by": "B", "target": "B:SHR", "card": "INTX"}, {"by": "C", "target": "C07", "card": "GW1"}]}
```

受け付けると、相手が考えて、次の番の問い（`{"n": 2, "kind": "abilities"}` など）に書き換わります。

### 受け付けなかったとき

JSON の誤り、種類（`kind`）の違い、札の反則、友好能力の宣言の形の誤り、最後の戦いの誤り（登場しない人物・無い役職・宣言の漏れや重複）などは、
プロセスを落とさずに同じ番号で聞き直します。見出しに `"error"` が付き、本文の末尾に理由が書き足されます。

```text
{"n": 1, "kind": "pc_cards", "error": "ValueError: 決定の順がずれている: 期待 pc_cards / ファイル abilities"}
...
！n=1 の答えは受け付けなかった: ValueError: 決定の順がずれている: 期待 pc_cards / ファイル abilities
  {"n": 1, "kind": "pc_cards", "choice": ...} を1行足して直す
```

直すときは、誤った行を消さずに `{"n": 1, ...}` の形で正しい行を1行足します（同じ番号は最後の行が使われます）。

### 相手の思考を速くする（SANGEKI_WORKERS）

相手が主人公の模型を持つ脚本家（`calcG`・`calcGB` など）なら、環境変数 `SANGEKI_WORKERS` に並列の数を指定すると、伏せ札の置き場所の組ごとの計算をプロセスで並べます。
選ぶ手は並べない場合と同じです（同じ seed の試合で札の列が一致することを確かめています）。p006 の1試合で、8 並列は約3.5倍速でした。

```bash
cd play && SANGEKI_WORKERS=8 python -m selfplay.play_cli --side pc --opp calcGB --seed 3 --script-file DIR/script_id --file DIR/d.jsonl --serve
```

対戦表のように試合を何本も並べて回すときは、メモリが足りなくなるので使わないでください（既定は 1＝並べない）。

### 終局

question.txt の1行目が `{"end": true, "result": {...}}` になり、`result.txt` に結果と全公開ログが書かれて、プロセスが終わります。

### 止まったとき・作り直し

決定ファイルは再生方式と互換です。常駐のプロセスが死んでも、

* 同じコマンドで `--serve` を起動し直せば、決定ファイルの分を進めてから続きの番で待ちます（`public_log.txt` は初めから書き直します）
* `--serve` を外して同じ決定ファイルで実行すれば、再生方式で同じ盤面まで作り直せます

### LLM のエージェントが使う手順

1. `--serve` のコマンドをバックグラウンドで起動する（ターミナルを占有するので）
2. `question.txt` の1行目が変わるのを待つ（Claude Code なら Monitor などで、1行目の `"n"` が増えるか `"end"` になるまで待つ）
3. `question.txt` を読み、決定ファイルに `{"n": N, "kind": ..., "choice": ...}` を1行足す
4. 1行目に `"error"` が付いたら理由を読み、同じ `N` で1行足して直す
5. `"end"` になるまで 2〜4 を繰り返す。終わったら（または途中でやめるなら）プロセスが残っていないことを確かめる

`pgrep -f` で待ち合わせると自分のコマンド行に一致してしまうので、プロセスは起動したときの PID で扱います。

### 目隠しの対戦（脚本を知らずに遊ぶ）

脚本の中身を知らない状態で主人公を務めるときは、`--script` の代わりに `--script-file` を使います。
脚本IDは別の人（または進行役の道具）がファイルに書いておき、遊ぶ側はそのファイルを開かずにパスだけ渡します。

```bash
cd play && python -m selfplay.play_cli --side pc --opp calcG --seed 3 --script-file DIR/script_id --file DIR/d.jsonl --serve
```

遊ぶ側は、脚本IDのファイル、`engine/scripts/` の脚本の中身を読まないでください（`--script-file` のときは `<file>.meta.json` に脚本IDの代わりにハッシュが残ります）。
question.txt・public_log.txt・result.txt には公開情報だけが出ます。

### 脚本家側（対AIモードで LLM が脚本家）

対AIモード（`ai_gm.py --mm claude`）で LLM が脚本家を務めるときも、同じ郵便受けの仕組みを使います。
問いは `<盤面のディレクトリ>/private/mm_question.txt`、答えは `private/mm_decisions.jsonl` に、上と同じ形（番号・聞き直し）で書きます。
決定の書式は[5章の脚本家側](#参考脚本家側--side-mmの決定)と同じです。LLM の型が持たない判断（ルールXの公開の選び方など）は自動の脚本家が受け持ちます。
